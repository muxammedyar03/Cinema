## Click: сохранение карты

`createInvoiceLink` отправляет только `title`, `description`, `payload`, `provider_token`, `currency` и `prices`. Поля `need_*` и `send_*` отсутствуют. В Cinema нет формы ввода, хранения PAN/CVV или API для сохранения карты.

Telegram показывает сохранённые платёжные credentials только если платёжная форма провайдера разрешает сохранение; также применяется защита аккаунта пользователя (двухэтапная аутентификация). Bot API не содержит параметра «сохранить карту». Поэтому повторный запрос карты сам по себе не доказывает ошибку Cinema.

Публичные документы Click не подтверждают сохранение карты в Telegram Click TEST. TEST и LIVE нельзя считать одинаковыми. LIVE-проверка пока не выполнена: нужны настоящий LIVE token, согласованная тестовая покупка и пользовательский Telegram-клиент. QA: включить 2FA, оплатить два раза, зафиксировать наличие «сохранить карту», версию клиента и тип token без значения token. Для TEST провести отдельную проверку и запросить у Click возможность `can_save_credentials`.

Альтернатива: отдельный checkout Click / открытие Click SuperApp с уже привязанными там картами. Это отдельная merchant-интеграция с callback, проверкой суммы/заказа и возвратами; заменять Telegram invoice простым URL нельзя. До подтверждения Click эта альтернатива не включена.

- https://core.telegram.org/bots/payments

## UI и реальные ограничения

Панель действия закреплена внизу и учитывает `safe-area-inset-bottom`; табы скрыты для фильма, выбора мест и заказа. В Telegram дополнительно используются MainButton/BackButton. При выборе мест вертикальные жесты Telegram отключаются только с API 7.7+ и восстанавливаются при выходе.

Схема вписывается по ширине, может панорамироваться и масштабироваться только внутри контейнера. На очень плотной схеме расширенные зоны нажатия пересекаются — выбирается ближайший центр места; для точного выбора используйте zoom. Внешний браузер сохраняет кнопку «назад» как fallback.

Rahmat отображается только при `payments/options.rahmat=true`. На текущем main Rahmat API ещё нет; полноценная интеграция находится в PR #23. При последующем merge #23 нужно согласовать его card-bind/OTP компонент с общей нижней панелью.
